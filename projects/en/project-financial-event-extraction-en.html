Financial Event Extraction

An agent system that turns financial documents into structured, timestamped events, scored against machine-readable ground truth. Its output is the event layer the Event-Driven Market Probability Engine is currently missing.

See the pipeline it feeds Back to portfolio

The premise

The differentiator is not the agent framework. "An agent that researches a topic and writes a report" is the 2026 equivalent of a React todo app, and the frameworks are a commodity. What almost nobody builds is an agent system with a real evaluation harness, and that is the entire reason to build this one.

LLM agents fail exactly the way data pipelines do: plausible, confident, wrong, and nothing raised. That is the same pathology my other work is built to catch, so the same discipline applies. The question is never "did it run", it is "is the output believable, and how would I know".

Structured ground truth is the unlock

Wherever a document ships machine-readable facts beside its prose, every number the model extracts has an authoritative value to check against. SEC filings carry XBRL: the model reads the text, XBRL holds the answer.

That converts "the agent seems to work" into a measurement, scored against a plain regex baseline. If it cannot beat regex, that belongs in the README as a finding rather than being quietly dropped.

Two verticals, one machinery

Macro — first, because it needs no new instruments

FOMC statements and minutes, Fed speeches, BLS and CPI releases. These apply to index and sector ETFs, which is the universe the probability engine already holds, so this vertical plugs straight into its unbuilt event layer.

FOMC statements are close to ideal to start with: short, published on a fixed schedule, deliberately formulaic, and changed sparingly. That makes a word-level diff between consecutive statements genuinely informative, and a structured hawkish/dovish delta per meeting a real feature rather than a vibe.

Corporate — same machinery, one more prerequisite

10-K, 10-Q, 8-K material events, Form 4 insider transactions, 13F holdings, earnings releases and calls. These apply to individual equities, so they need the downstream universe extended before they have anything to attach to.

Form 4 filings are free on EDGAR, which makes "what executives say versus what they do with their own holdings" a far more tractable signal than anything gated behind transcript licensing.

Target architecture

Target architecture

Two deliverables, useful separately. The brief is the demo artifact; the structured events are what a probability model consumes. Neither depends on the other existing.

Three readers, two outputs

A coordinator dispatches each new document to a numeric agent (XBRL facts, actuals, KPIs), a language agent (tone, hedging, risk framing), and a change agent (this document against the prior ones). Results converge into two deliverables that are useful separately: a human-readable research brief, and structured events written to SQL.

The second is the one that matters downstream. The probability engine's raw.events table already expects exactly this shape: a publication timestamp, an event type, and actual / forecast / previous values, from which a surprise measure falls out directly. Its pipeline can then align each event to an effective trading date and build event-conditional features on instruments it already holds. The one piece still open on that side is the event-to-asset mapping, which currently holds a placeholder.

The change agent is the interesting one

Summarising a single document is a commodity. Detecting that "we continue to see very strong demand" became "demand remains healthy, although customers are becoming somewhat more cautious" is not, and the identical technique reads an FOMC statement dropping "patient". That requires a memory per entity rather than per document:

Build order

Sequenced so each stage is measurable before the next one adds ambiguity. Ground truth first, subjective judgement last, orchestration only around things that already work.

1 · Ingestion, no LLM

Poll the EDGAR API and the Fed/BLS release calendars, store raw documents with their publication timestamps, pull XBRL facts. Fully deterministic. This is the ground-truth layer everything else is scored against.

2 · Extraction, scored

The model reads numbers out of prose; XBRL already holds the answer. Report accuracy against a regex baseline and categorise the failures. The credibility experiment.

3 · FOMC diffing

The macro vertical and the cheapest path to something the probability engine can consume. Consecutive-statement diffs plus a structured hawkish/dovish delta. Small corpus, fixed schedule, no access problems.

4 · Narrative extraction

Demand language, pricing, risk framing, guidance. No ground truth here, so evaluation shifts to inter-run agreement and a hand-labelled sample.

5 · Change detection

Entity memory across documents. The actual product, and the part that is not a commodity.

6 · Orchestration

LangGraph wrapping stages that already work, with confidence-based routing to manual review rather than silently writing a guess. Sixth, not first.

Constraints taken seriously

Deterministic wherever possible

SQL writes, formatting and validation are plain code. The model is reserved for what genuinely needs language understanding. Every step that does not require judgement is one that cannot hallucinate, cost money per call, or return something different on the next run.

Evaluation is a component, not a final step

Accuracy against ground truth, cost and latency per document, and named failure categories are measured continuously rather than reported once at the end. That is the difference between a portfolio piece and a demo: a demo shows that it worked once, a harness says how often it works and how it breaks.

Point-in-time discipline carries over

Each document is used as of its publication timestamp, never a restated or amended value. A filing's acceptance time is when the information became public; a macro release's initial print is what the market actually saw. Using revised data is the same class of error as any other lookahead bias.

Small samples, many candidate features

Quarterly filings give roughly four observations per company per year, and FOMC gives eight meetings. Both are small and correlated. Test twenty candidate features against one label and one will look significant on chance alone, which is easy to mistake for a discovery on a sample this thin.

Non-determinism, contained

Extraction is not repeatable and is not meant to be. Several models read each document, their mean becomes the event value, and the spread between them is a usable confidence measure. That non-determinism stays at the ingestion boundary, with raw responses stored, so everything downstream remains a deterministic function of what was stored.

Where the ground truth runs out

"Management confidence 0.82" is unfalsifiable as stated. Anything subjective is either reframed as a relative change against the same entity's prior document, or hand-labelled on a sample with agreement reported. Transcript access is the main open blocker, which is why transcripts are last and nothing before them depends on it.
